# M10 — Extended device library: implementation plan and tracker

Shared tracking file for GitHub milestone **M10 — Extended device library**
(milestone 11). Status lives in the checkboxes and the tracker table below; tick
an item only when it is merged with green validation and, where observable from
a deck, a C-golden comparison. Detailed cross-milestone status still belongs in
[TODO.md](../../TODO.md); update it as each slice lands.

- Base: `main` after the v0.4.0 / M9 merge (`work/m9` at `39bc85a`).
- Work branch convention: `work/m10-<slice>` (e.g. `work/m10-jfet`).
- Fixture convention: `conformance/netlists/m10_<device>_<analysis>.cir` with
  goldens captured deliberately via `cargo xtask golden capture` and reviewed.
- No full SPICE parity is claimed for any device; every unported level,
  parameter or flag fails with `SpiceError::NotYetPorted` naming its C file.

## Verified baseline (`work/m9`)

- `J`, `Z`, `T`, `O`, `U`, `Y` are listed in `src/netlist/card.rs` but have no
  instance grammar; `src/devices/registry.rs` marks them `Pending`
  (`stub_factory` → `NotYetPorted`).
- `ModelFamily` (`src/devices/models.rs`) knows `r c l d npn pnp nmos pmos sw
  csw`; no `njf`/`pjf`/`nmf`/`pmf`/`ltra`/`urc`/`txl`.
- MOS: only level 1 (`src/devices/mos1.rs`, rejects `selector != 1`). The Q/M
  grammar (`src/netlist/parser/transistor.rs`) states it does no binning.
- Subcircuit-local `.model` renaming and scoped lookup are **already done** by
  #18 ([SUBCIRCUITS.md](SUBCIRCUITS.md)); #109's remaining work is binning plus
  a C cross-check of the combination.
- Transient breakpoints come only from source waveforms
  (`SystemBreakpoints`, `src/devices/linear.rs:327`, consumed in
  `src/analysis/companion.rs`). There is no device-driven breakpoint path.
- `Device::timestep_limit` (`src/devices/traits.rs:651`) exists and is used by
  the switch; `Device::accept`, `truncation_slots`, `depends_on_frequency`,
  `assemble_small_signal`, `noise`, `distortion` and `sensitivity` hooks exist.
- Shared building blocks: `devices::limiting` (`DEVpnjlim`, `DEVfetlim`,
  `DEVlimvds`), junction/charge code in `devices::nonlinear`, Meyer charge and
  junction geometry in `devices::mos1`.

## Slice 2 — model binning (#109)

C: `inpgmod.c::INPgetModBin`, `inp2m.c`, `inpfindl.c`, `subckt.c` (renaming).

- [x] Read `inp2m.c`/`INPgetModBin` and record exactly which model types C bins
      and the selection rule. Recorded in
      [MODEL_SCHEMAS.md](MODEL_SCHEMAS.md#model-binning-109): only `M`, only
      when no exact name exists; `.<digits>` suffixes; only BSIM3 (8/49),
      BSIM4 (14/54), HiSIM2 (68), HiSIM-HV (73); **both** edges inclusive with
      a 1e-9 m absolute tolerance (not `min <= L < max`); `W = w/nf` only under
      `wnflag`, both scaled by `scale`; `m` ignored; no match / missing `l`,`w`
      is C's "could not find a valid modelname".
- [x] Resolver extension (`src/devices/binning.rs`, `ModelResolver::select_bin`):
      on a missing exact name, choose among `<name>.<n>` candidates. Failures
      are parse errors listing every candidate and its location. **Divergence
      from this plan:** overlap is not an error — C binds the last declared
      matching bin (its model table is prepended), and adjacent bins always
      overlap on their shared edge, so the port does the same.
- [x] Interaction with scoped renaming matches C: the innermost frame with an
      exact or binned match captures the reference (even if none of its bins
      fits), its set is emitted as `x1.nch.<n>`; root models that would join it
      are rejected.
- [x] C bins only unported families: the resolver is unit-tested with
      BSIM-level cards and a selected bin ends in the family's existing
      `NotYetPorted` level error (`m1 binned to model 'nch.2': ...`). Level-1
      `.N` cards are not binnable in C and are rejected as in C.
- [ ] C goldens: not possible until a binnable family simulates (slice 10).
      Instead the opt-in `tests/c_binning_reference.rs` compares the bin C binds
      (`show all : model`) with the port's choice on 21 decks, including bin
      edges, the multiplier and subcircuit-local sets. #109's acceptance box
      stays open until BSIM3 goldens exist.
- [x] Update the transistor grammar doc comment and SUBCIRCUITS/MODEL_SCHEMAS
      (also ARCHITECTURE, MAPPING, VERIFICATION, TODO.md).
- [ ] Deck inputs still missing: `.options scale`/`wnflag` (rejected/unknown
      today) and instance `nf`/`wnflag` (not in the `M` grammar). The selection
      already takes them via `BinOptions`/`ModelResolver::with_bin_options`.

- [ ] AC: exact frequency-dependent complex stamp (`traacld.c`,

- [ ] Transient: Branin/method-of-characteristics model.

Tests and acceptance

## Definition of done (every slice)

- `cargo fmt --all -- --check`
- `cargo clippy --workspace --all-targets --locked -- -D warnings`
- `cargo test --workspace --locked` (stable and `+1.89.0` if dependencies or
  compiler-facing code change)

- Opt-in C checks with `NGSPICE_BIN` pass for the new fixtures

  baseline decks

## Risks and open questions

- **Binning scope (confirmed):** C bins only BSIM3/BSIM4/HiSIM models, so
  slice 2 delivered the resolver and a C selection cross-check; deck-visible
  simulation and goldens wait for slice 10, which only has to accept the
  BSIM3 selector in `levels()` and dispatch its factory.
- **Device breakpoints (slice 3)** change the companion driver's breakpoint
  contract; it needs its own review and must not disturb existing source
  breakpoint/left-right-limit behaviour or goldens.
- **MOS refactor (slice 4)** risks subtle MOS1 drift; gate it on byte-stable
  existing goldens before adding level 3.
- **BSIM size:** `b3ld.c`/`b4ld.c` are thousands of lines; plan code generation
  for parameter tables and treat it as its own milestone.
- Noise, distortion and sensitivity for new devices are follow-ups unless a
  slice explicitly includes them; until then they must error, not return zero.
